# 参考项目分析：AzurLaneAutoScript（ALAS）

> 分析对象：`D:\projectPath\AzurLaneAutoScript`（只读分析，没有改动任何文件；它正在给实例 0 跑碧蓝航线）。
> 目的：确定 zjcs 自动化沿用哪些技术栈和架构，哪些先不做。

## 1. ALAS 的技术栈

| 方面 | ALAS 用的 | 说明 |
|---|---|---|
| 语言 | Python 3.7.6（自带 `toolkit\` 解释器） | 依赖用 pip-compile 锁版本 |
| 图像识别 | opencv-python、numpy、Pillow | 颜色判断 + 模板匹配（`cv2.matchTemplate`，TM_CCOEFF_NORMED） |
| 设备连接 | adbutils（走 adb server 的 socket）、uiautomator2 | adb 可执行文件来自 `config\deploy.yaml` 的 `AdbExecutable` |
| 截图 | ADB / DroidCast / aScreenCap / scrcpy / nemu_ipc / **ldopengl**（雷电专用 DLL） | 实例 0 的 ALAS 用的是 ldopengl + MaaTouch |
| 点击 | ADB `input tap` / minitouch / MaaTouch / uiautomator2 | 点击区域内随机取点 |
| OCR | cnocr 1.2.2 + mxnet（自训练小模型，只认数字和大写字母） | 可选 zerorpc 远程 OCR 服务 |
| 配置 | yaml 定义参数 → 生成 `config_generated.py` → 用户配置 json | 任务用 `config.Group_Arg` 读自己的参数 |
| 日志 | rich | `logger.hr()` 打分隔标题，`logger.attr()` 打属性 |
| 界面 | pywebio + uvicorn 的 Web GUI，Electron 外壳 | 多进程管理多个配置 |

## 2. ALAS 的架构要点

```
alas.py  ──  AzurLaneAutoScript：调度循环 loop() + 每个任务一个同名方法
module/
├─ base/      Button、Template、ModuleBase(appear / appear_then_click / interval)、Timer、utils
├─ device/    Device = Screenshot + Control + AppControl；卡死检测、连点检测
├─ config/    配置读写、调度（NextRun、ServerUpdate、任务优先级）
├─ ui/        Page 页面图 + ui_goto / ui_ensure / ui_get_current_page
├─ handler/   弹窗、登录处理
├─ ocr/       数字和文字识别
└─ <功能>/     每个游戏功能一个目录，带生成的 assets.py
assets/       按模块存放模板图片
dev_tools/    button_extract.py：截图 → 模板图 + assets.py
```

- **调度**：每个任务有 `Enable` 和 `NextRun`。循环里挑出到期的任务（按优先级），执行后用 `task_delay(server_update=True)` 推到下一次服务器刷新（会换算服务器时区）。同一任务连续失败 3 次就停下来通知人工。
- **异常分级**：`TaskEnd` 当成功；`GameStuckError` / `GameTooManyClickError` 保存错误截图后重启游戏或跳过任务；`GamePageUnknownError`、`ScriptError`、`RequestHumanTakeover` 直接停止。
- **识别原语**：`appear(button, offset=0)`，offset 为 0 时比较区域平均色，不为 0 时在区域 ± offset 范围内做模板匹配，并把匹配到的偏移带给点击。`interval` 参数防止同一个按钮被连点。
- **页面导航**：每个页面登记一个只在本页出现的 `check_button`，页面之间用 `link(按钮, 目标页)` 连成图；`ui_goto` 从目标页反向 BFS，在当前页点「下一跳」按钮，直到目标页出现。
- **保险**：60 秒内只截图不点击判定卡死；最近 15 次点击里同一个按钮占 12 次判定点击无效。
- **商店模块**：按「物品优先级过滤串」挑选商品（`GeneralShop_Filter`），刷新是一个布尔开关、最多刷新 1 次；**没有按折扣购买的逻辑**。

## 3. zjcs 沿用了什么、简化了什么

| ALAS | zjcs 第一阶段 | 原因 |
|---|---|---|
| Python 3.7 + toolkit | Python 3.11 + 项目内 `.venv` | 本机已有 3.11；依赖只有 opencv、numpy、Pillow、PyYAML |
| `alas.py` 调度循环、任务同名方法、失败 3 次停止 | 同样的结构：`zjcs.py` 的 `ZjcsAutoScript.loop()` | 直接沿用 |
| `Button` / `ModuleBase.appear` / `Timer` / `utils` | 同名同语义，接口基本一致 | 直接沿用 |
| `Page` 页面图 + `ui_goto` 反向 BFS | 同样的实现 | 直接沿用 |
| 卡死检测、连点检测、错误截图 | 同样的规则（60 秒 / 15 次里 12 次），另加 5 分钟的「长等待」模式给匹配、战斗用 | 直接沿用 |
| button_extract（涂黑截图找区域） | 区域写在 `assets/<模块>/define.yaml`，脚本裁图生成 `assets.py` | 更适合用 ADB 截图 + 坐标标注的工作方式 |
| adbutils + 自动替换/重启 adb server | 直接调用雷电自带的 `adb.exe`，**不执行 kill-server / start-server** | 实例 0 的 ALAS 共用同一个 adb server，不能互相踢掉 |
| 多种截图方式（含 ldopengl） | 先只做 ADB 原始像素截图（约 0.2 秒/张）和 png 截图 | 够用；ldopengl 以后需要提速时再加 |
| yaml → 生成代码 → json 配置 | 单个 `config/zjcs.yaml`，按 `Group_Arg` 读取；运行状态另存 `zjcs.state.json` | 第一阶段没有 GUI，不需要生成器 |
| 服务器时区换算 | 同样支持：`ServerUpdate` + `ServerTimezone` | 本机是 UTC+9，游戏是 UTC+8 |
| 游戏崩溃/卡死时自动重启并重新登录 | **不做**，出错就保存截图并停下来 | 重启游戏、登录流程都还没探索，需要你确认 |
| OCR、Web GUI、推送通知 | **不做** | 不在第一阶段需求里；OCR 等到确实需要读数字（例如公会战比较战力）时再定方案 |
